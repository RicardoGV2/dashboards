# Handoff — 2026-09-22

This document is the continuity note for the next agent working on **RicardoGV2/dashboards**.

## Product direction

The project is not a single finance dashboard. It is an extensible **infinite-canvas visual workspace** where different capabilities can coexist: notes, text, shapes, images, animation, finance maps, future spreadsheets, code, Mermaid/flowcharts, video, files/projects, tasks and other utilities.

New features should be **added**, not implemented by replacing earlier ones.

### Existing capabilities that must remain working

- Infinite canvas with pan, anchored zoom, fit and viewport culling.
- Select, move, resize, keyboard movement and accessible object list.
- Notes, text and shapes.
- Image upload (PNG/JPEG/WebP/GIF, current 2 MB cap), image assets, alt/description text.
- Animated 3D cube with speed, direction, axis, perspective, color and pause controls.
- Undo/redo through validated atomic commands.
- IndexedDB local autosave with single-writer protection.
- JSON import/export and schema migration.
- Responsive/touch interaction and pinch zoom.
- GitHub Pages deployment from the checked-in production root build.

Do **not** remove one of these when adding a new visual mode.

## Current architecture

Source modules:

- `packages/document`: versioned serializable document schema and strict validation.
- `packages/engine`: camera math, history/commands, rendering adapters.
- `packages/widgets`: constructors/defaults for basic widgets and cube.
- `packages/finance`: reusable finance-demo scene factory.
- `packages/storage`: IndexedDB adapter.
- `apps/web`: editor shell, toolbar, inspectors and browser input handling.

The engine/document core remains framework-independent TypeScript. The DOM renderer is an adapter.

## Document schema

Current work introduces **schema version 3**.

Schema v3 adds a generic `connections` graph while preserving assets and all previous node types.

Node kinds:

- `note`
- `text`
- `shape`
- `image`
- `cube`
- `finance`

Finance is intentionally one visual capability, not a replacement for generic canvas nodes.

Connections are generic enough to support later flowcharts/dataflow:

- `structure`
- `incoming`
- `outgoing`
- `transfer`
- `shared`

Version 1 and version 2 workspaces migrate forward automatically. Unknown future schemas must still fail safely rather than silently deleting data.

## Finance visual prototype

The **Finance** toolbar button inserts a self-contained demo scene centered near the current viewport.

The demo is visual/sample data only. It does **not** connect to a real bank yet and must never be described as live bank integration.

The scene contains two reusable person modules:

- Ricardo
  - Revolut
  - BOI / Bank of Ireland
  - Work income
  - Rent
  - Utilities
  - Spotify
  - Groceries
  - Savings
- Janet
  - AIB
  - Revolut
  - Work income
  - Rent
  - Subscriptions
  - Groceries
  - Savings

Each finance child has an `ownerId` pointing to its person. This lets multiple people reuse the same visual structure with different institutions and data.

### Person expand/collapse

Each person card has an expand/collapse control. Collapsing a person hides their owned bank/source/destination nodes and any connections whose endpoint is hidden. The underlying document data remains intact.

Future work can make the whole person card clickable, but drag-vs-click behavior must be handled deliberately to avoid accidental collapse while moving a node.

### Money-flow visuals

The SVG connection layer is independent from the DOM node layer.

- Green = incoming.
- Coral/red = outgoing.
- Blue = transfer/savings.
- Purple dashed = shared relationship.
- Blue dashed = structural bank relationship.

Animated particles move along money-flow paths. Reduced-motion users do not receive the moving particles.

Moving a node automatically changes the rendered connection geometry because links are calculated from document coordinates each render.

### Finance inspector

Selecting a finance person shows demo overview metrics and their banks in the right inspector. Selecting a bank/source/destination shows relevant visual metadata.

This inspector is presentation scaffolding. Real finance calculations must later be driven from typed transaction data, not hand-authored display values.

## Why the connection graph is generic

The connection model was added to the document instead of hard-coding finance lines into the UI. The same primitive can later support:

- flowcharts,
- data dependencies,
- Mermaid-derived diagrams,
- file/project relationships,
- task dependencies,
- account transfers,
- graph visualizations.

Do not couple the generic connection model to banking APIs.

## Real bank integration — later

Do not place bank credentials or API secrets in the GitHub Pages frontend.

A future live-finance implementation needs a secured backend/provider layer for:

1. bank authorization,
2. account identity,
3. transaction ingestion,
4. normalized transactions,
5. recurring-payment detection,
6. mapping transactions to visual entities,
7. push/poll updates,
8. permissions and revocation.

The visual document should reference stable semantic account/entity IDs. Credentials belong outside the document.

## Current visual-design direction

The application uses the dark visual treatment from first load. Finance scenes add finance-specific overlays and flow styling, but they do not control the base theme:

- deep navy infinite canvas,
- glowing directional flows,
- person hubs,
- bank nodes visualized as small institution/city tiles,
- outgoing destination tiles,
- a live-demo banner and flow legend,
- richer finance inspector.

Other widget types continue to exist and render in the same workspace.

Theme state and feature state are intentionally separate: `app-theme-dark` is applied globally in the HTML shell, while `finance-mode` only reflects whether finance objects exist. Do not tie the base theme to Finance again.

## GitHub Pages

Pages currently publishes the repository root. Source lives in `apps/web`, but the production build must also be refreshed into root `index.html` + `assets/`.

Run:

```sh
npm run build:pages
```

Commit the generated production files with the corresponding source changes. A feature that exists only under `apps/web` will not appear on the live Pages site until the root build is refreshed.

## Non-negotiable product principle

**Preserve composability.** The workspace should be able to contain a finance map next to an image, cube, note, code block, spreadsheet and future widgets on the same infinite canvas.
